# 정보 손실 통신소 초등학생 실사용 개선 설계

- 작성일: 2026-07-18
- 대상 버전: v0.2.0 → v0.3.0
- 승인된 난이도 기준: 3학년이 혼자 읽고 수행할 수 있는 쉬운 말을 공통 기준으로 사용한다. 5~6학년 개념어는 없애지 않고 짧은 풀이를 함께 제공한다.
- 범위: 학생용 문구, 선택 복구, 되돌아가기, 비활성 행동 안내, 결과 화면 요약
- 제외: 사건 판정 규칙 변경, 개인정보 저장, 로그인, 교사용 평가 기능, 전체 시각 디자인 교체

## 1. 실사용 테스트 근거

390×844 화면에서 3~4학년 기본 활동의 시작 → 연습 → 사건 선택 → 비교 → 처음부터 끝까지 보기 → 뜻을 지킨 문장 선택 → 결과를 직접 수행했다. 5~6학년 확장 활동에서는 시작 → 사건 선택 → 사건 설명까지 수행했다.

### 확인된 마찰

1. 연습 활동에서 이전 문장과 다음 문장의 말을 함께 누르면 오답이 되지만, 한쪽만 골라야 한다는 설명과 선택을 한 번에 지우는 기능이 없다.
2. 빈 답안과 과다 선택이 모두 “한 번 더 골라 보세요”로 안내되어 학생이 무엇을 고쳐야 하는지 알기 어렵다.
3. `인접 단계`, `표현 조각`, `근거 뜻`, `전이`, `원문`, `보존`, `복구`, `확실성`, `인수인계`가 3학년의 혼자 읽기 기준보다 어렵다.
4. 비활성화된 `다음 비교` 버튼만 보여서 먼저 해야 할 행동을 놓칠 수 있다.
5. 비교 화면에서 사건 설명으로, 전체 보기에서 비교로, 문장 선택에서 전체 보기로 돌아갈 수 없다.
6. 결과 화면은 390px에서 약 1,415px 높이이며, 찾지 않은 변화 종류에도 `확인한 변화가 없어요`가 반복된다.
7. 5~6학년 사건의 `출처`, `확실성`, `예정`은 중요한 개념이지만 현재 화면에는 즉시 이해할 풀이가 없다.

### 유지할 장점

- 360px와 390px에서 가로 넘침이 없다.
- 사건 선택부터 결과까지 5단계 현재 위치가 보인다.
- 선택 영역은 44px 이상이며 키보드로 조작할 수 있다.
- 개인정보를 저장하지 않고 고정된 가상 사건만 사용한다.
- 복수의 올바른 전달문과 엄격한 의미 판정 규칙을 유지한다.

## 2. 권장 접근

문구만 바꾸지 않고 학생이 막혔을 때 스스로 복구할 수 있는 작은 기능을 함께 추가한다. 기존 화면 구조와 도메인 판정 규칙은 보존하고, 학생이 읽는 레이블·피드백·이동 버튼·결과 요약만 집중적으로 개선한다.

## 3. 학생용 문구 원칙

### 공통 원칙

- 한 문장에는 한 행동만 쓴다.
- 동작 버튼은 명사보다 동사로 시작한다.
- 화면에서 쓰지 않아도 되는 전문어는 쉬운 말로 바꾼다.
- 학습 개념상 필요한 전문어는 `개념어(쉬운 풀이)` 형태로 처음 보이는 곳에 설명한다.
- 정답 피드백은 칭찬 뒤에 실제로 맞힌 내용을 말한다.
- 오답 피드백은 `무엇이 문제인지 → 어떻게 고칠지` 순서로 말한다.

### 고정 문구 대응

| 현재 문구 | 개선 문구 |
| --- | --- |

### 5~6학년 개념 풀이

- `조건` → `조건(어떤 때인지)`
- `출처` → `출처(누가 알려 줬는지)`
- `확실성` → `확실성(예정인지 확정인지)`
- `예정` → 첫 사건 설명에서 `예정(아직 바뀔 수 있음)`
- `확정` → 첫 사건 설명에서 `확정(이제 정해짐)`
- 사건 제목 `가상 학교 방송 인수인계` → `가상 학교 방송 이어 전하기`
- 사건 목적 `방송 인수인계에서 확인된 조건과 시간을 빠뜨리지 않아요.` → `방송 내용을 이어 전할 때, 어떤 때인지와 시간을 빠뜨리지 않아요.`

## 4. 화면별 설계

### 시작 화면

- 역 이름과 기록실 분위기는 유지한다.
- `항로` 은유는 학생의 선택 버튼에서는 `활동`으로 바꾼다.
- 5~6학년 설명은 `조건, 누가 알려 줬는지, 아직 바뀔 수 있는지도 살펴봐요.`로 쓴다.

### 연습·비교 화면

- 3단계 제목을 `1. 달라진 말 고르기`, `2. 어떻게 달라졌나요?`, `3. 왜 그렇게 생각했나요?`로 표시한다.
- 1단계 설명은 변화 종류에 맞게 바꾼다.
  - `내용이 빠짐`: `이전 문장에서 사라진 말을 골라요.`
  - 나머지 변화: `다음 문장에서 달라지거나 새로 생긴 말을 골라요.`
- 현재 선택 수와 `고른 것 지우기` 버튼을 문장 카드 바로 아래에 둔다.
- 지우기는 현재 답안의 문장 선택과 근거 선택만 비우고, 이미 확인한 변화 기록은 지우지 않는다.
- 다음 버튼이 비활성화되어 있을 때 `먼저 내 답 확인을 눌러요.`를 버튼 가까이에 항상 표시한다.

### 오답·정답 피드백

- 아무것도 고르지 않았을 때: `먼저 달라진 말을 하나 고르고, 그 이유도 골라 보세요.`
- 필요한 것보다 많이 골랐을 때: `말을 너무 많이 골랐어요. 달라진 말만 남겨 보세요.`
- 변화 종류만 틀렸을 때: `고른 말은 다시 살펴볼 수 있어요. 어떻게 달라졌는지 한 번 더 생각해 보세요.`
- 정답일 때: `잘 찾았어요. 고른 말과 이유가 서로 맞아요.`
- 화면에 `전이`라는 단어를 노출하지 않는다.

### 되돌아가기

- 연습 화면: `시작 화면으로`
- 사건 비교: `사건 설명으로`
- 처음부터 끝까지 보기: `비교로 돌아가기`
- 뜻을 지킨 문장 선택: `전체 변화 다시 보기`
- 돌아갈 때 이미 확인한 변화와 완료 기록은 유지한다.
- 비교 화면에서 사건 설명으로 돌아갈 때 아직 확인하지 않은 현재 선택만 비운다.

### 처음부터 끝까지 보기

- 제목은 `처음 문장에서 마지막 문장까지`로 쓴다.
- 각 카드의 상태 레이블은 `남아 있음`, `사라짐`, `새로 생김`을 사용한다.
- 값이 없는 줄은 `없음`을 유지하되 색과 기호만으로 뜻을 구분하지 않는다.

### 뜻을 지킨 문장 선택

- 제목은 `뜻을 지킨 문장을 골라 다시 보내요`로 쓴다.
- 틀린 선택은 `꼭 있어야 할 내용이 빠졌어요. 시간·장소·조건을 다시 살펴보세요.`처럼 실제 빠진 종류를 쉬운 레이블로 알려 준다.
- 완료 버튼이 비활성화되어 있으면 `뜻을 모두 지킨 문장을 골라야 활동을 마칠 수 있어요.`를 표시한다.

### 결과 화면

- 위쪽에는 `처음 달라진 곳`, `다시 넣은 중요한 내용`, `내가 고른 문장`만 먼저 보여 준다.
- `내가 찾은 변화`에는 실제로 찾은 변화 종류만 렌더링한다.
- 찾지 않은 변화 종류와 반복되는 `확인한 변화가 없어요` 카드는 생략한다.
- `근거`는 `이유`로 바꾼다.
- 보조 버튼 `전달 보존 기록 보기`는 `완료 기록 보기`로 바꾼다.

## 5. 컴포넌트와 상태 경계

- `app/components/shared.ts`
  - 학생용 변화 이름과 쉬운 의미 종류 레이블을 한곳에서 제공한다.
  - 도메인 enum과 ID는 변경하지 않는다.
- `app/components/SelectionSummary.tsx` 신규
  - 선택 수, 선택 지우기, 비활성 다음 행동 안내를 재사용 가능한 형태로 제공한다.
- `app/components/WelcomeTutorial.tsx`
  - 쉬운 문구, 선택 지우기, 시작 화면 이동을 제공한다.

  - 쉬운 문구, 변화별 선택 방향, 선택 지우기, 사건 설명 이동을 제공한다.
- `app/components/Outcome.tsx`

  - 화면 이동 콜백과 현재 미확인 답안 초기화를 담당한다.

  - 판정 규칙은 유지하고, 빈 선택·과다 선택·종류 불일치를 구분한 학생용 피드백만 개선한다.
- `domain/cases.ts`
  - 5~6학년 사건 제목·목적과 학생에게 보이는 설명 문장만 쉽게 바꾼다.

각 코드 파일은 500줄 미만을 유지한다.

## 6. 데이터와 이동 흐름

1. 학생이 문장과 이유를 고른다.
2. `judgeStageChange`가 기존 의미 규칙으로 정답을 판정한다.
3. 오답이면 상태에 맞는 구체적인 쉬운 피드백을 보여 준다.
4. 정답이면 확인한 변화 ID를 유지하고 현재 선택만 비운다.
5. 학생이 이전 화면으로 가도 확인한 변화 ID는 유지한다.
6. 결과 화면은 저장된 학습자 발견 중 실제로 존재하는 변화 종류만 보여 준다.

개인정보, 브라우저 저장소, 쿠키, 서버 데이터베이스는 사용하지 않는다.

## 7. 접근성·반응형 기준

- 모든 새 버튼은 최소 높이 44px을 유지한다.
- 선택 지우기와 되돌아가기에는 보이는 텍스트 레이블을 사용한다.
- 현재 단계는 기존 `aria-current="step"`을 유지한다.
- 피드백은 기존 `aria-live`와 오답 초점 이동을 유지한다.
- 비활성 버튼 안내는 해당 버튼과 `aria-describedby`로 연결한다.
- 360px, 390px, 200% 확대에서 가로 스크롤이 없어야 한다.
- 결과 화면에서 첫 번째 주요 행동이 모바일 첫 화면 아래쪽에서 지나치게 멀어지지 않도록 빈 결과 카드를 제거한다.

## 8. 테스트 설계

### 도메인 테스트

- 빈 선택, 과다 선택, 변화 종류 불일치가 서로 다른 쉬운 피드백을 반환한다.
- 정답 판정과 `matchingChangeIds`는 기존과 동일하다.

### 렌더링·컴포넌트 테스트

- 금지 문구 `인접 단계`, `표현 조각`, `근거 뜻`, `전이`, `전체 사슬 점검`, `전달 보존 기록`이 학생 화면에 없다.
- 5~6학년 개념 풀이와 쉬운 사건 제목이 보인다.
- 결과 화면은 실제로 찾은 변화 종류만 보여 준다.

### E2E 실사용 테스트

- 이전·다음 말을 함께 선택한 뒤 `고른 것 지우기`로 복구할 수 있다.
- 비활성 다음 버튼 안내가 보인다.
- 연습 → 시작, 비교 → 사건 설명, 전체 보기 → 비교, 문장 선택 → 전체 보기 이동이 된다.
- 돌아온 뒤 이미 확인한 변화는 유지된다.
- 3~4학년 사건 1과 5~6학년 사건 4를 끝까지 완료한다.
- 360px·390px·200% 확대·키보드·axe·저장소 없음 검사를 유지한다.
