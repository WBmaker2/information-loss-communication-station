# 2026-08-31 초등학생 관점 UX 개선 계획

## 점검 목표

초등학교 3~6학년이 교사 설명 없이도 “어느 문장에서 무엇을 하나 고르고, 왜 그런지 고른 뒤, 언제 다음으로 가는지” 알 수 있는지 확인합니다. 사용자가 요청한 `elementary-webapp-ux-orchestrator`의 `full` 모드로 기준선 화면과 학습 흐름을 먼저 점검하고, 계획을 기록한 뒤 구현합니다.

- 주 페르소나: 초3~4 준호 — 설명을 길게 읽기보다 눈에 띄는 버튼부터 누릅니다.
- 가드레일 페르소나: 초5~6 서윤 — 조건·출처·예정/확정 같은 근거를 기대합니다.
- 점검일: 2026-08-31
- 공개 기준선: https://wbmaker2.github.io/information-loss-communication-station/
- VoiceOver 검증: 제외

## 기준선에서 찾은 문제

| 우선순위 | 문제 | 학생에게 보이는 어려움 |
| --- | --- | --- |
| P1 | “두 문장에서 고르기”라는 안내와 실제 판정(변화 종류에 따라 한쪽 조각만 선택)이 다름 | 대응 조각을 양쪽에서 모두 눌렀다가 “너무 많이 골랐어요”를 받음 |
| P1 | 불완전한 전달문과 안전한 문장을 함께 고르면 합집합 뜻 검사가 통과함 | 틀린 문장을 취소하지 않아도 결과에 남음 |
| P2 | 긴 풀이 도움말이 첫 선택보다 먼저 표시됨 | 320px 화면에서 첫 선택지가 y=1323~1425까지 밀림 |
| P2 | 시작 화면 제목·설명이 길고 모바일 CTA가 아래에 있음 | 320×800에서 `연습 시작`이 y=828이라 첫 화면 밖에 있음 |

## 구현 계획 및 수용 기준

1. 아직 찾지 못한 변화의 종류에 맞춰 `이전/다음 문장`과 구체적인 한 조각을 안내합니다.
2. 안내된 카드와 버튼에 `gi-pulse` 아우라를 주고, 선택한 조각은 펄스를 멈춰 선택 상태를 보여 줍니다.
3. 비교 카드를 `지금 할 일`과 함께 풀이 도움말보다 먼저 배치합니다.
4. 시작 문구를 짧게 바꾸고 모바일 여백을 줄여 CTA가 첫 화면에 보이게 합니다.
5. 선택한 전달문을 개별 검증하여 하나라도 불완전하면 완료 버튼을 잠그고, 다시 눌러 취소하는 방법을 알려 줍니다.
6. 업데이트 내역에 이번 개선을 기록하고, 같은 시나리오를 자동화 테스트로 다시 실행합니다.

수용 기준은 P0와 미해결 P1이 없고, 320/375/1280px에서 가로 넘침 없이 첫 행동을 찾으며, 오답 후 취소·재선택으로 회복하는 것입니다. 정적 문장 비교 활동이므로 새 시뮬레이션 엔진은 추가하지 않습니다(`not-needed`).

## 라우팅 기록

`ui-ux-pro-max`는 이번 런타임에서 `filesystem-only`였고, 첫 runtime-available 대안인 `design-system` 경로를 선택했습니다. 의존성 preflight는 `ready`였으며 기존 `node_modules`를 재사용했습니다.
